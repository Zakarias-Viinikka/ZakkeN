# Shared Memory - Zndroid Project

## Architecture Highlights

- **Authoritative source**: yrs CRDT blobs in `pages.blobbed_page`.
- **Queryable source**: `every_block_in_existence`, ordered by `(frac_position ASC, my_id_as_given_by_yrs ASC)`.
- **Sync strategy**: intent-based. `client_love_letter` stores `LoveLetterSketch` (serialized intent) plus a yrs diff snapshot per edit.
- **DB concurrency**: `DbManager` serialises all access with a `Mutex` (Android port of the wasm worker queue). One writer at a time across the whole app is enforced by `z.zndroid.WriteLock`. `executeNative` and `withTransaction` run their bodies on `Dispatchers.IO`, so UI callers suspend instead of running yrs / uniffi work on the main thread.
- **Layers**: reads (`db/reads`) -> writes (executor, `executor/`) -> batcher (`editor/PageBatcher`) -> public actions (`actions/`). Nothing skips a layer. `db/schema` holds the `ColumnDescriptor` objects every read in `db/reads` uses. Not true everywhere: StorageAccess, MigrationManager, DbManager and several tests still index columns by position (see MISSING_AND_STALE.md).
- **Builder/executor**: every write goes through the Rust builder (`rustlib.data_builder_...`) then the Kotlin executor in `z.zndroid.executor`. `executor/Operations.kt` mirrors `executor_of_what_the_builder_built_.../page_executor/operations.rs` one to one. `executor/TableWrites.kt` mirrors `table_writes/*.rs`.
- **Editing**: `editor/PageSession` owns the rows and every editing rule as a method. `editor/PageBatcher` holds an ordered queue of `Edit / Add / Delete / Move` entries, debounces 500ms (cancelling only the delay under `debounceLock`; the flush runs in its own coroutine), flushes inside one `WriteLock` + `withTransaction`, walks the queue in order. Consecutive Edits are squashed per block; any non-edit entry flushes the pending edit run first. On any failure the transaction rolls back, the boss is now ahead of the DB, so `GlobalPopupManager.showError` and `onFailed` are dispatched to Main and ViewPage rebuilds everything from the DB (drop queue, destroy boss). `PageSession.applyRemoteRows(fetchMirror)` flushes pending edits first, then reads fresh mirror rows and updates `rows` in place on Main to preserve focus and IME. This replaces the old `diffBuffer / lastPersistedText / syncUiStates / APP_LOCKED` machinery.
- **Flush on leave**: top-bar back, system BackHandler, lifecycle ON_STOP, and DisposableEffect.onDispose (async, on the batcher's own scope so composition-scope cancellation can't abort it).
- **Focus**: `PageSession.pendingFocus = (blockId, offset)`. Each block's effect, when it matches, awaits a frame, calls `requestFocus`, sets the selection, clears. Retries for a few frames if the block isn't laid out. The scroll is `animateScrollToItem` inside the same per-block effect (there is no page-level effect), so it only runs for a composed block.
- **Page operations**: `actions/createNewPage`, `actions/renamePage`, `actions/disablePage`, `actions/moveBlockToAnotherPage`. Each takes WriteLock, runs one transaction, one commit (`moveBlockToAnotherPage` flushes any registered open sessions for source and target pages before taking `WriteLock`). `DbManager.hardDeletePage` is dev-only.
- **Schema**: `z.zndroid.db.schema` holds `ColumnDescriptor<T>` objects per table. `SchemaCanaryTest` asserts each descriptor's expected type. Migrations via `MigrationManager` + frozen snapshots in `db/migrations/schemas/`. `assertLatestMatchesBlueprints` compares the live Rust blueprints against the latest frozen Kotlin version. A host-side schema drift detector (plan at `android_app/schema_drift_detector/PLAN.md`) is planned; it compares the Rust blueprints against the frozen snapshot and `TableDescriptors.kt` with per-column, per-field reports, and runs during the Android build.
- **Session id**: per-process. `SessionManager.initialize` reads the last stored id, sets `currentSessionId` to that + 1 synchronously, and persists it. Navigation does not bump it — `MainActivity` no longer registers a destination-changed listener. A read error or unparsable stored value leaves the counter where it was (with a popup) rather than resetting to 0. `SessionMonotonicityTest` asserts it stays stable during a session.
- **Disable = hide**: `disablePage` marks the page and all its blocks disabled. The nav menu filters disabled pages out. If the page being disabled is currently open on the device that sends the disable, the user sees a popup and keeps working; the page just stops appearing in the menu.
- **Logging**: `Logger.kt` writes to Logcat and the `logs` table. Inside a transaction, log lines buffer in `DbTransactionElement.logBuffer`; on commit the buffer is dropped, on rollback it is flushed outside the failed transaction. The transaction is found through the coroutine context (a `DbTransactionElement`), so a thread switch inside a transaction still routes to the right buffer. Source parameter passed explicitly at every call site (no stack-trace introspection; R8 obfuscation breaks it, though `isMinifyEnabled` is false today). The write scope has a `SupervisorJob` and a failed write is reported to Logcat. Only `ViewPageLogs` (three helpers, all called from `ViewPage`) uses `Logger` (grep 2026-11-13), so the in-transaction buffering is untested in production and the table is nearly empty.
- **Dev Tools**: page at route `test_results` (both the nav button and the route are gated by `BuildConfig.DEBUG`; the page class compiles into release but is unreachable), nav button labelled "Dev Tools". `DevCheckRegistry.checks` is the one list of checks. Run sequentially. Each logs `Log.i("DevCheck", "id=... status=PASS|FAIL|SKIP detail=...")` (first 4000 chars). The last line is `Log.i("DevCheck", "summary pass=N fail=M skip=K")`. Sections: schema.*, migration, session.monotonic, mirror.vs_yrs, outbox.integrity, outbox.replay, ops.*, client_vs_server (reserved, reports `SKIP`). Actions section (wipe/seed) is separate. A check with detail also logs a second line, `id=... st=<STATUS> stack=...` (first 8000 chars); the `detail=` on the main line is the message only.
- **Server sync**: Android talks to `zakken_server` over a websocket. The wire is Rust behind uniffi (`zakken_server/client_internals/server_link/`, wrapping `shared_internals` which is shared with web); Kotlin business logic lives in `z.zndroid.sync.owner_of_interacting_with_server` and mirrors web's `owner_of_interacting_with_server/` one file per file. `client_love_letter` is the outbox (every committed write appends a row, `SendLoop` drains oldest-first). `seen_server_letters` deduplicates pushed letters (also in-memory). `key_value_storage` holds `server_url`, `server_user_name`, `client_drift_version`, `should_i_drift_popup`. `kickSend()` (`actions/Kick.kt`) is a `Channel.CONFLATED` that wakes `SendLoop`. Reconcile (server-wins) and wipe are wired into `MainPages/RecoveryPage.kt` via `Recovery.kt`; the recovery screen is reachable only from `NavPage`'s lonewolf banner. `OpenPageRegistry` tracks open pages so incoming letters merge into a live ViewPage rather than being deferred. Verified end-to-end 2026-11-15 for connect + login + receive + apply + ack.
- **E2E**: external Python/Appium harness at `../e2e_android_tests/`. Three tests: `test_multiple_blocks`, `test_page_lifecycle` (user-visible), `test_dev_checks` (navigates to Dev Tools, runs all checks, asserts `fail=0`, prints each failure id + message). Whole run happens inside one external transaction opened by the debug `TestTransactionReceiver`; teardown rolls it back.
- **Popup severity**: `GlobalPopupManager.show(msg)` (info) vs `showError(msg)` (error, `ERROR:` prefix in the snackbar, `Log.e` to logcat). Harness reads popups from logcat tag `GlobalPopup` because snackbars render behind Dialog windows. Rule: anything that means "something went wrong" is `showError`.

## Schema (as of V4)

- `pages`: id, page_id, blobbed_page, page_status, version, is_main_menu_page
- `backlinks`: id, page_that_holds_link_id, page_being_linked_to_id, disabled, version
- `every_block_in_existence`: id, is_title, is_part_of_main_menu_page, content, my_id_as_given_by_yrs, id_of_page_i_belong_to, frac_position, page_is_disabled
- `client_love_letter`: id, snapshot_of_edit, love_letter_sketch, session_id, target_id
- `key_value_storage`: id, key, value
- `incoming_love_letters`: id, love_letter, target_page_id
- `logs`: id, timestamp, level, category, source, session_id, message
- `seen_server_letters`: id, letter_id (V4; Android doesn't read or write it yet — reserved for the sync receive loop)

## Known bugs

- **`text_diff.getDiff` unequal-length replacement (still open in Rust; worked around on Android).** Equal-length replacements like `getDiff("a", "b")` return `Replace`, but unequal-length replacements with no common prefix/suffix (e.g. `getDiff("aX", "hello")`) return `Insert("hello", 0)` instead of `Replace`, prepending `"hello"` onto `"aX"`. `PageSession` now uses a local Unicode code-point prefix/suffix differ (`computeDiff`) that emits `DiffResult.Replace` whenever both old and new middles are non-empty, matching `generate_love_letters` in `web_diff_viewer`.
- **(`edit_text_block` miscounts on non-ASCII for Delete/Replace — still open.)** `yrs` counts `chars().count()` for the delete range but `Doc::new()` uses byte offsets by default, so `å/ä/ö/emoji` inside a Delete/Replace range can misplace. Not exercised by any current e2e test. `renamePage` always sends a Replace, so renaming a page whose current title holds such characters is exposed; its readback check (`rename readback mismatch`) would turn a misplaced edit into a rolled-back "Rename failed", not corrupt data. Typed Delete/Replace edits in blocks that contain them are exposed too. From reading; not run. `ops.unicode_edit` in `OpsChecks.kt` reproduces it; it's removed from the `DevCheckRegistry` list until the Rust side is fixed so it doesn't block the suite. Re-add it once the bug is fixed.
- **`edit_text_block` labels errors as `"edit_text_block_insert"`.** Stale from an earlier method name. Left alone (report only).

- **Open Android-side issues** (bugs, dead code, release exposure, positional column reads) are tracked in [MISSING_AND_STALE.md](MISSING_AND_STALE.md), not here.
